# Synch Server 설치 및 운영

## 설정

| 옵션 | 설명 |
|---|---|
| public_url | 기기에서 실제 접속하는 원점 주소. 예: `http://192.168.45.62:8787`. 경로 없이 지정 |
| allowed_emails | 새 계정을 만들 수 있는 이메일 목록. 하나 이상 필요 |
| request_timeout_ms | HTTP 요청 제한 시간. 기본 300000ms(5분), 최대 1500000ms(25분) |

이메일은 앞뒤 공백을 제거하고 소문자로 비교합니다. 목록에서 제거해도 기존 계정이
삭제되거나 로그인이 차단되지는 않습니다. 최초 관리자 비밀번호 옵션은 없으며,
허용 목록에 포함된 이메일로 Synch 웹 화면에서 직접 가입합니다.

`localhost`는 접속하는 기기 자신을 의미합니다. Obsidian이 실행되는 모든 기기에서
접근할 수 있는 HA 장치 IP나 DNS 이름을 사용하세요. API 포트는 컨테이너 내부에서
8787이며 HA 네트워크 설정에서 호스트 포트를 변경할 수 있습니다.

웹 UI에 HTTPS를 사용하려면 별도 리버스 프록시가 필요합니다. 이 App은 HTTP 서버이며
인증서 설정 없이 URL만 HTTPS로 바꾸면 접속되지 않습니다. 일부 브라우저 암호화 기능은
보안 컨텍스트를 요구할 수 있으므로 웹 기능은 HTTPS 환경에서도 검증하세요.

## Obsidian 연결

1. App 설정에 사용할 이메일을 추가하고 시작합니다.
2. Synch 웹 화면에서 해당 이메일과 새 비밀번호로 가입합니다.
3. Obsidian에서 Synch 플러그인을 설치하고 설정의 Self-hosted server에 `public_url`과
   동일한 주소를 입력합니다. 끝에 `/`를 붙이지 않습니다.
4. 로그인하고 테스트 볼트를 생성합니다.
5. 두 번째 기기에서도 같은 서버와 계정으로 연결하여 동기화를 확인합니다.

이 패키지는 이메일/비밀번호 로그인과 디스크 저장 방식을 제공합니다.
원본의 선택 기능인 Google/GitHub OAuth와 외부 S3 설정은 이 버전의 옵션에 포함하지 않았습니다.

## 외부 접속

HTTPS 프록시는 HA 장치의 매핑 포트로 전달하고 WebSocket Upgrade를 허용해야 합니다.
큰 첨부파일에 맞춰 업로드 용량 제한, 버퍼링 및 프록시 timeout을 설정하세요.
별도 S3 주소는 필요하지 않습니다. Home Assistant 원격 접속만 설정했다고 해서
Synch 포트가 자동으로 공개되지는 않습니다.

Ingress 경로 재작성과 Home Assistant 자동 로그인은 제공하지 않습니다.
웹 화면과 Obsidian은 Synch 자체 계정을 사용합니다.

## 데이터와 백업

`/data/synch`에는 `app.db`, 볼트별 SQLite 및 암호화 파일이 저장됩니다.
`/data/synch-secrets.json`은 세션/동기화 토큰 인증 키입니다. 둘을 함께 백업하고 복원해야 합니다.
기존 데이터가 있는데 키 파일이 없으면 시작을 거부하며 임의로 새 키를 만들지 않습니다.

HAOS 백업에서 이 App을 포함하세요. `cold` 백업 동안 서버가 중지되므로 동기화가 잠시 끊깁니다.
볼트 암호화 비밀번호는 별도로 보관해야 합니다. 업데이트 전에는 전체 App 백업을 만드세요.
DB 마이그레이션은 원본 서버가 시작 시 실행합니다.

기존 Osync 데이터 자동 이관은 제공하지 않습니다. Synch에서 새 볼트를 만들어 연결하세요.

## 문제 확인

- 설정 오류: App 로그의 `[app]` 메시지에 따라 URL/이메일 목록을 수정합니다.
- Origin 오류: 접속 URL의 스킴·호스트·포트가 `public_url`과 일치하는지 확인합니다.
- 가입 거부: 정확한 이메일이 `allowed_emails`에 있는지 확인합니다.
- 접속 불가: 로그의 `[self-host] listening on 0.0.0.0:8787`과 포트 매핑을 확인합니다.
- 프록시에서 동기화 중단: WebSocket 전달과 프록시 timeout을 확인합니다.

이 서버는 Bun 대신 Node.js를 사용합니다. 다만 Proxmox `kvm64`에서의 실행은 검증하지 않았으며,
이 App만을 이유로 현재 정상 작동 중인 VM CPU 설정을 바꿀 필요는 없습니다.
